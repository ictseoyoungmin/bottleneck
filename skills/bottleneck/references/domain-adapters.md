# Domain Adapters

Bottleneck is a general work topology, not a software-only rule.

## Software / agentic coding

Skeleton: interfaces, routes, data model, mocks.

ACTIVE: one subsystem to production quality.

CLOSED asset: library/module/service with tests, docs, integration contract.

## Interactive world / simulation

Skeleton: coarse terrain, navigation, placeholder systems, camera/input contract.

ACTIVE: one high-leverage system such as vegetation, water, vehicle physics, solver, or viewer.

CLOSED asset: visually and computationally hardened reusable system with budgets and demo.

## Dashboard / application UI

Skeleton: final layout regions and real data contracts.

ACTIVE: one main chart, editor, table, or simulation viewer.

CLOSED asset: responsive, accessible, performant component with loading/error/empty states.

## Research

Skeleton: hypothesis/evidence matrix and study contract.

ACTIVE: one falsifiable hypothesis or analysis unit.

CLOSED asset: reproducible result with assumptions, provenance, uncertainty, and counter-checks.

Do not hide relevant confounders merely to create isolation. Provide the minimum sufficient authoritative context.

## Business / product strategy

Skeleton: value proposition, target user, constraints, measurable outcomes.

ACTIVE: one decision bottleneck — acquisition, pricing, retention, distribution, unit economics, etc.

CLOSED asset: evidence-backed decision module with adoption/rejection rule.

## Creative work

Skeleton: world invariants, character state, causal obligations, style constraints.

ACTIVE: one scene, sequence, asset family, or interaction beat.

CLOSED asset: final-quality artifact plus compressed state changes for downstream work.
